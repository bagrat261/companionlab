# Локальный агент: 7 ноября 2026

Приоритет пользователя — улучшить computer use на собственной локальной модели. Полный аудит безопасности остановлен; этот этап не расширяет его и не обновляет upstream заново. Голос Fish Audio, Discord и новая архитектура памяти в этом этапе не изменялись.

## Изменения

- `Start-Qwen.cmd` и `ci/run-ollama.ps1`: запуск существующей Qwen через установленную Ollama, отдельные данные `out/ollama-profile`, без скачивания весов и импорта настроек Capri. Для отсутствующей модели/недоступной Ollama выдаётся ошибка. Перед включением агентного режима проверяется заявленная поддержка tools.
- `app/Brain.cs`: явный opt-in `OllamaSteps` включает существующий цикл планирования для нативной Ollama; локальные OpenAI-compatible серверы и встроенный движок остаются на старом пути. При отказе поддерживать tools модель помечается как toolless в текущей сессии. Для распознанной команды ответ без инструментов получает одно напоминание; повторный ответ без действий заменяется сообщением о невыполнении.
- `app/Capri.cs`: настройка `OllamaAgent`, по умолчанию false для старых профилей, и подключение регрессионного теста. Наш launcher включает её в своём отдельном профиле. Разрешения инструментов по-прежнему проверяет существующий `Companion.DoTool`; Guarded не расширялся.
- `app/OllamaChecks.cs`: воспроизведение ответа о состоянии окон без вызова инструмента, затем проверка двух последовательных tool rounds и передачи ошибки обратно модели через настоящий HTTP-протокол с тестовым сервером.
- `ci/test-ollama-brain.ps1`: отдельная проверка настоящего Brain из EXE с локальной моделью; разрешён только настоящий `list_windows`. Сначала отдельно проверяется мост к Windows, затем его счётчик сбрасывается — эта подготовка не засчитывается как вызов инструмента моделью. В отчёт не записываются заголовки окон.

Локальная модель: `hf.co/LEONW24/Qwen3.5-9B-Uncensored:Q4_K_M`, метаданные Ollama: 9.65B параметров, tools/thinking/completion/vision. Это заявленные возможности модели, а не гарантия качества действий.

## Наблюдения и проверки

До изменений реальная модель отвечала по-русски и сохраняла историю, но не вызывала запрошенный инструмент. После включения планировщика контекст 8K оказался недостаточным: запрос занимал 13714 токенов. Поэтому новый профиль использует 16K и 16 сообщений истории. На реальной Ollama подтверждён `context_length = 16384`; `size_vram = 6145357905` байт. Это размер модели в VRAM по данным Ollama, а не суммарное потребление всей видеокарты или benchmark скорости. 32K доступен явным параметром, но в этом этапе не проверялся.

Ещё до защиты от ответа без действий модель выдала выдуманный список окон. Новый тест с таким ответом дал **0 PASS / 1 FAIL**. После исправления целевая suite дала **20 PASS / 1 LIMIT / 0 FAIL / 0 SKIP**: SmokeOllamaPlanning, SmokeBrainBodies, SmokeWorkingOut, SmokeCharacters, SmokeCharacterRegressions. Собраны Windows-приложение и установщик. Полная suite не прогонялась.

Финальный живой probe прошёл: русские ответы Capri/Luna, история 2 → 4 при смене персонажа, и модель действительно вызвала `list_windows`, выполнив настоящий Windows-инструмент. Контекст 16K подтверждён самим сервером. После проверки модель, загруженная только этим probe, выгружается. Локальный JSON: `out/ollama-profile/probe/result.json`; целевые тесты: `out/qwen-final-checks/smoke-test.txt`. Эти файлы игнорируются Git.

Во время промежуточных проверок Qwen меняла транслитерацию имени или называла Luna «Лана». Это ограничение качества модели вынесено в отдельный `CharacterNamesMatched`/LIMIT и не скрывается за успешной проверкой транспорта/истории. В финальном прогоне оба имени совпали. Детерминированные проверки профилей остаются отдельными.

## Границы результата

Реальные клики, ввод в браузер, чтение почты, отправка сообщений, voice/vision inference и многошаговая реальная задача не тестировались. Многошаговая последовательность проверена HTTP fixture, а живая модель — одним безопасным инструментом чтения. Это работающий начальный путь локального агента, не гарантия надёжного управления любыми приложениями.

Защита от ответа без инструментов действует для команд, распознанных существующим `Hands.Wants`; она не доказывает корректность каждого результата и не покрывает все формулировки. Следующий этап: выбирать небольшой набор инструментов под задачу, затем проверить одну реальную задачу в тестовом окне с наблюдаемым результатом и аварийной остановкой. Это одновременно уменьшит переполнение контекста и даст конкретную проверку computer use. Русский голос Fish Audio и официальный Discord-бот — отдельные последующие этапы.
