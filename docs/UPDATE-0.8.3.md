# Обновление CompanionLab до Capri 0.8.3

Дата проверки: 5 ноября 2026. Upstream release: [v0.8.3](https://github.com/lachydotmcg/capri-desktop/releases/tag/v0.8.3), SHA `82a5c6b8fa2a873a4d04f21131fcd76c25620dd9`. Обновлялись исходники и наша локальная сборка; установленная оригинальная Capri не обновлялась и её данные не изменялись.

## Что вошло

Выполнен обычный merge релиза с сохранением истории Git и наших изменений. Конфликты разрешены в `app/Capri.cs`, `app/Setup.cs`, `ci/build-windows.ps1`, `cross/Capri.Cross.csproj`. В Windows-сборку включены новые исходные файлы upstream: mods/skins/colors, интерфейс mods, SoundsLike и Husk. В `cross/` сохранён новый Mainframe оригинала; также пришёл исходный проект Quest. Это не означает, что Quest или Mac-перенос CompanionLab протестированы.

Сохранены наши профили, собственные данные/установщик, ручное обновление и безопасные значения по умолчанию. Новый skin hook применяется к встроенной Capri, а выбранный внешний профиль продолжает использовать свои проверенные ресурсы. Новые notices Husk включены в ресурсы приложения/установщика и выдаваемые файлы лицензий.

Две регрессии воспроизведены тестами до исправления (9 PASS / 1 LIMIT / 2 FAIL), затем исправлены:

- Новый необязательный Friends-бит в сохранённых разрешениях 0.8.3 больше не сбрасывает валидные настройки. Поддержаны оба формата upstream, отсутствующие/некорректные настройки остаются Guarded.
- `HuskHook.Data` использует CompanionLab, а не каталог оригинальной Capri.

Upstream call mode использует управление пользовательским клиентом и аудио звонка, а не отдельного официального Discord-бота. В обычном Windows CompanionLab он отключён: сохранённый CallMode не включается при старте, переключатель сообщает ограничение, tool calls для call_say/call_errand и распознанного подключения к звонку возвращают явное объяснение. Исходные smoke-проверки доступны только в тестовом режиме. Это ограничение конкретных call entrypoints; общий агент управления компьютером не является универсальным фильтром всех возможных действий внутри Discord. Discord-интеграция через бота остаётся будущим этапом.

Husk по умолчанию выключен. Его включение через Mainframe может менять настройки hooks Codex/Claude; автоматическое включение и установка hooks в ходе обновления не выполнялись. Code mods upstream требуют согласия на импорт и привязаны к хешу файла; моды не устанавливались. Не считать это полноценной sandbox для доверенного C# кода.

## Фактические проверки этой версии

| Проверка | Результат |
| --- | --- |
| Windows app + installer, встроенный csc / .NET Framework | Собраны успешно, предупреждения сериализуемых полей сохранены |
| `ci/test-characters.ps1` | 26 PASS |
| SmokeCharacters + SmokeCharacterRegressions | 11 PASS / 1 LIMIT / 0 FAIL / 0 SKIP |
| SmokeCloudBrains + SmokeBrainBodies | 17 PASS / 1 LIMIT / 0 FAIL / 0 SKIP |
| Installer `--verify` | 10 PASS / 1 LIMIT; реальная установка/удаление не выполнялись |
| Настоящий Brain через существующую Gemma 4 E4B Q4_0 | Русские ответы Capri и Luna; история 2 → 4, одна и та же модель |

Локальная сборка: `out/windows/CompanionLab.exe` и `CompanionLab-Setup.exe`. Локальные артефакты: `out/update-083-green/smoke-test.txt`, `out/update-083-ai/smoke-test.txt`, `out/update-083-package/packaging-test.txt`, `out/update-083-live/live-brain-result.json`. Они исключены из Git; в репозитории сохранены исходники тестов и этот отчёт. Реальный локальный inference использует проверенный llama.cpp b11669, читает существующие GGUF, после проверки завершает только собственный сервер.

Полная новая smoke-suite 0.8.3 не прогонялась. В отчёте первой итерации остаются реальные полные результаты для 0.8.2 с известными upstream-ошибками; их нельзя переносить на 0.8.3. Live Gemini/OpenRouter, русский/английский TTS, vision inference, новая интерактивная GUI-сессия, macOS/Linux/Quest, моды и Husk end-to-end не проверены. Нативные focused smoke-проверки действительно открывают формы и вызывают реальное меню профилей; новая ручная desktop-automation после остановки пользователем через Esc не запускалась.
