# CompanionLab: первая итерация

Личный некоммерческий [форк CompanionLab](https://github.com/bagrat261/companionlab) проекта [Capri Desktop](https://github.com/lachydotmcg/capri-desktop). Обновлён до стабильного [релиза 0.8.3](https://github.com/lachydotmcg/capri-desktop/releases/tag/v0.8.3), commit `82a5c6b8fa2a873a4d04f21131fcd76c25620dd9`. Для облачного продолжения используйте `main`: [инструкция](docs/CLOUD-HANDOFF.md). Исходная проверенная итерация на 0.8.2 сохранена в `companionlab/iteration-1-v0.8.2`; её исторический отчёт не описывает результаты тестов обновления.

Изменения и ограничения обновления: [UPDATE-0.8.3.md](docs/UPDATE-0.8.3.md). Call mode и автоматическое подключение к звонкам отключены в обычном режиме CompanionLab: Discord запланирован отдельным модулем официального бота. Husk выключен по умолчанию; включение может устанавливать hooks Codex/Claude и требует осознанного выбора в настройках.

Сохранены исходный C# 5, WinForms и .NET Framework 4.8. `README.md` содержит исходную документацию Capri; для этого форка следуйте настоящему файлу. Установщики оригинальной Capri для обновления CompanionLab отключены.

## Запуск на Windows

### Своя Qwen через Ollama

Для установленной `hf.co/LEONW24/Qwen3.5-9B-Uncensored:Q4_K_M` запустите Ollama, затем откройте `Start-Qwen.cmd` в корне репозитория. Используется существующий нативный Ollama transport Brain, без новой загрузки модели и без облачного API. Данные этого запуска хранятся отдельно в `out/ollama-profile`; данные установленной Capri не импортируются. Сначала нужна сборка `out/windows/CompanionLab.exe` по инструкции ниже.

У нового профиля русский язык, контекст 16384 токена и 16 последних сообщений. Голос, наблюдение за экраном, wake word и автозапуск выключены. Разрешения Guarded сохранены. Последующие пользовательские изменения этих настроек сохраняются; launcher выбирает локальную Ollama и включает `OllamaAgent` только для модели с заявленной поддержкой tools. Явный `-ContextTokens 16384` меняет контекст существующего профиля; без этого параметра сохранённый размер не перезаписывается.

Для другой уже установленной модели:

```powershell
.\ci\run-ollama.ps1 -Model 'имя из ollama list'
```

Подготовка без открытия интерфейса и отдельная проверка настоящего Brain:

```powershell
.\ci\run-ollama.ps1 -Model 'hf.co/LEONW24/Qwen3.5-9B-Uncensored:Q4_K_M' -PrepareOnly
.\ci\run-ollama.ps1 -Model 'hf.co/LEONW24/Qwen3.5-9B-Uncensored:Q4_K_M' -ProbeOnly
```

ProbeOnly выполняет настоящие запросы к локальной модели и разрешает только реальный Windows-инструмент `list_windows`. Заголовки окон остаются в локальном inference и не включаются в итоговый JSON. Проверка отказывается загружать вторую модель, если другая уже работает; модель, загруженную только для проверки, выгружает после завершения. Это проверка разговора, истории и чтения окон, а не кликов, браузерных задач или многошагового computer use.

В upstream `Brain.WorksOut()` включал внешний многошаговый цикл только для облачных провайдеров. В CompanionLab для нативной Ollama добавлен явный opt-in `OllamaAgent`: используется существующий цикл до 12 раундов и существующие проверки разрешений. По умолчанию старые профили остаются на прежнем пути. При явном отказе модели поддерживать tools цикл отключается для этой модели в текущей сессии. Локальные OpenAI-compatible серверы и встроенная Gemma этим флагом не включаются.

Для распознанной маршрутизатором команды локальный цикл не принимает ответ без вызова инструмента: даёт модели одно напоминание, затем возвращает сообщение о невыполнении. Это не универсальная проверка правдивости: классификация запроса и интерпретация результатов всё ещё могут ошибаться. Подробный результат итерации: [LOCAL-AGENT-ITERATION.md](docs/LOCAL-AGENT-ITERATION.md).

На реальной Qwen запрос со всеми схемами инструментов занимал примерно 13714 токенов и не помещался в 8K. Поэтому агентный профиль начинает с 16K. Это ещё не полноценное управление бюджетом контекста: большой список инструментов следует сокращать под задачу, а длинные результаты и историю — сворачивать. Тест цепочки инструментов использует HTTP fixture, реальная проверка модели отдельно читает только окна.

### Прямой запуск и существующая Gemma

Готовая локально собранная программа: `out/windows/CompanionLab.exe`. Её можно запустить без установки. Необходим .NET Framework 4.8, обычно уже присутствующий в Windows 11. Современный .NET SDK и Ollama не являются обязательными зависимостями Windows-интерфейса.

```powershell
.\out\windows\CompanionLab.exe
```

На этом компьютере найдены уже установленные оригинальной Capri веса Gemma 4 E4B и vision-проектор. Для запуска с ними без повторной загрузки весов:

```powershell
.\ci\run-existing-gemma.ps1 -ModelDirectory "$env:LOCALAPPDATA\Capri\brain\models"
```

Скрипт проверяет SHA-256 обоих GGUF и закреплённого llama.cpp b11669, запускает один loopback-сервер и CompanionLab с отдельными данными `out/existing-gemma`. Веса оригинала читаются по существующему пути; настройки, история и файлы оригинальной Capri не импортируются. Если другой companion/model process уже работает, скрипт останавливается с объяснением, а не загружает вторую модель. При выходе из CompanionLab завершается только запущенный скриптом сервер. Закрытие Mainframe может лишь свернуть приложение: используйте Quit в меню для полного выхода.

В этой поставке проверенный архив движка уже лежит в `out/runtime`; в свежем checkout при его отсутствии скачивается только около 32 MB runtime с проверкой закреплённого SHA-256. Проверка реального AI без интерфейса:

```powershell
.\ci\run-existing-gemma.ps1 -ModelDirectory "$env:LOCALAPPDATA\Capri\brain\models" -ProbeOnly
```

ProbeOnly вызывает настоящий Brain из собранного EXE, проверяет русский ответ Capri/Luna, сохранение истории и той же модели, затем освобождает GPU. Реальные ответы сохранены в `verification/live-brain.json`. После остановки computer-use через Esc новый интерфейс автоматически не запускался; интерактивный launcher подготовлен для вашего ручного запуска.

Для отдельного экспериментального каталога данных:

```powershell
.\out\windows\CompanionLab.exe --data-dir "C:\CompanionLab-TestData"
```

По умолчанию данные находятся в `%LOCALAPPDATA%\CompanionLab`: настройки, ключи, история, память, профили и журнал `actions.log`. Приложение не переносит данные из `%LOCALAPPDATA%\Capri`. В среде sandbox путь LocalApplicationData может быть перенаправлен самой Windows.

Контекстное меню персонажа или значка трея → **Characters (Capri)** → выбор профиля. **Open character folder** открывает каталог `%LOCALAPPDATA%\CompanionLab\characters`. Ошибки профилей доступны через **Profile errors**. Во время ответа, голосового разговора, активной задачи или перетаскивания сначала завершите действие; для задачи используется существующий Esc.

Встроенная Capri доступна без внешних файлов. Для второго профиля скопируйте папку `characters/examples/luna` в открытый каталог персонажей. Пример Luna использует исходную графику Capri и отключённый голос; это пример другого профиля, а не новый нарисованный персонаж.

LLM выбирается в существующем **Open Capri Mainframe → BRAIN**. Провайдер, модель, ключи, история и память общие для всех персонажей. Можно использовать свой Ollama или совместимый локальный API, либо поддерживаемый облачный провайдер. Ollama не найден в PATH; существующая Gemma работает через встроенный в Capri тип движка llama.cpp, без Ollama. Новые веса и облачные ключи не устанавливались; реальный локальный текстовый запрос проверен.

Голос выбирается через **VOICE**. Загрузка локального голоса/распознавателя выполняется при явном выборе соответствующей функции, а не просто при первом запуске. Голосовой разговор включает микрофон по действию пользователя. Wake word и Listen for Capri по умолчанию выключены. После явного включения wake word приложение может подготавливать его зависимости при следующем запуске.

Не запускайте исходную Capri Setup поверх форка. Не обходите предупреждения Windows. Не устанавливайте VB-CABLE для проверки профилей: он нужен только отдельной функции подачи голоса в виртуальный микрофон.

## Сборка из исходников

Используйте обычный Windows PowerShell из корня репозитория. Достаточно встроенного `csc.exe` и Windows SDK. Если SDK установлен:

```powershell
.\ci\build-windows.ps1
```

Без установленного SDK можно получить только официальные reference metadata Microsoft, без установки компонентов в систему:

```powershell
.\ci\prepare-windows-metadata.ps1
.\ci\build-windows.ps1 -MetadataDirectory .\out\sdk\contracts\ref\netstandard2.0
```

Используется фиксированный пакет `Microsoft.Windows.SDK.Contracts 10.0.26100.1` с проверкой SHA-256. Ответные файлы компилятора исключают ограничение Windows на длину командной строки.

Результаты: `out/windows/CompanionLab.exe`, `CompanionLab-Setup.exe`, `LICENSE.md`, `NOTICE.md`, `OFL-ShareTechMono.txt`. Установщик подготовлен для `%LOCALAPPDATA%\CompanionLab`, с отдельными ярлыками, записью удаления, startup-именем и маркером установки. В рамках разработки установка/удаление в профиль пользователя не выполнялись.

## Проверки

```powershell
.\ci\test-characters.ps1
.\out\windows\CompanionLab.exe --smoke-test "$PWD\out\character-smoke" --only SmokeCharacters,SmokeCharacterRegressions
.\out\windows\CompanionLab-Setup.exe --verify "$PWD\out\package-check"
.\ci\build-windows.ps1 -MetadataDirectory .\out\sdk\contracts\ref\netstandard2.0 -SmokeTest -SmokeSeconds 900
```

`--verify` проверяет упаковку, извлекает payload в указанный каталог и рисует окна установщика; он не выполняет установку. Полный smoke-набор содержит сотни исходных проверок и может выполняться несколько минут. Его отчёт содержит PASS, FAIL, SKIP и LIMIT. Ограничения и воспроизводимые исходные сбои перечислены в `ITERATION-1-REPORT.md`; зелёный тест загрузчика не означает, что весь исходный набор зелёный.

## Данные и разрешения

- Новый профиль установки получает Guarded: приложения, музыка и сочетания клавиш доступны; более сильные действия проходят существующий запрос разрешения.
- Отсутствующие/повреждённые permissions не превращаются в Trusted. Восстановление после повторных сбоев сохраняет ключи, но возвращает консервативные настройки.
- Check-ins, follow-ups, автоматическое запоминание увиденного, Discord presence и startup по умолчанию выключены. Сохранённые явные настройки пользователя продолжают действовать.
- `actions.log` содержит UTC-время, имя инструмента и этап requested/returned/threw, без аргументов, текста пользователя и секретов. `returned` не означает успешное действие. Журнал ограничен текущим файлом около 1 MiB и одной предыдущей копией.
- Исходные transcript/memory/error-логи сохраняются отдельно и могут содержать пользовательский текст. Это не защищённое хранилище секретов и не полная защита от prompt injection.
- Windows-ключи провайдеров сохраняются существующим механизмом DPAPI CurrentUser. Их не нужно помещать в character.json.

## GitHub

GitHub CLI в проверенном окружении отсутствует. Подготовлен локальный Git-репозиторий с полной историей и отдельной веткой; облачный форк не создан и ничего не опубликовано.

Создайте fork оригинального репозитория в своём GitHub, затем выполните, заменив YOUR_LOGIN своим именем:

```powershell
git remote add origin https://github.com/YOUR_LOGIN/capri-desktop.git
git push -u origin companionlab/iteration-1
```

Оригинал остаётся remote `upstream`. Эти команды связывают уже готовую локальную историю с вашим форком.
