# CompanionLab — отчёт первой итерации

Получена собираемая Windows-основа с работающим Character System и проверенным настоящим локальным AI. Полная стабилизация унаследованного тестового набора ещё не завершена: итоговый полный прогон содержит 9 FAIL. Эти сбои не скрыты за зелёными профильными тестами.

## 1. Что обнаружено в исходном проекте

Основа — [Capri 0.8.2](https://github.com/lachydotmcg/capri-desktop/releases/tag/v0.8.2), commit `a5bc79592995359b347075d92233d0654f84fbe2`, последний стабильный релиз на момент проверки 4 ноября 2026 года. Последующие изменения main не подмешивались. Полная [техническая карта](docs/technical-map.md) описывает исходники и историю релизов.

Windows-клиент использует C# 5, WinForms/GDI+ и .NET Framework 4.8. Он компилируется встроенным Windows csc.exe, без современного SDK dotnet. В окружении отсутствовал Windows SDK metadata; добавлена воспроизводимая сборка с официальным Microsoft.Windows.SDK.Contracts 10.0.26100.1 и закреплённым SHA-256. Глобальные инструменты не устанавливались.

Основная архитектурная проблема — большой Capri.cs со связанными состояниями UI, desktop и smoke-сценариями. Переписывать приложение для первой итерации не потребовалось: новый код вынесен в каталог профилей и отдельные partial-файлы.

## 2. Что уже сделал оригинальный автор

В исходниках уже были 2D-анимации, прозрачное окно, перетаскивание/сидение/броски, click-through, поддержка рабочих областей нескольких мониторов, fullscreen-настройки, mini-player и реакции на игры/музыку.

Также уже реализованы Brain/LLM-провайдеры, собственный llama-server и Ollama, OpenAI-compatible API, tool calls и многошаговые Job, UI Automation, захват экрана/OCR, память и transcripts, ASR/TTS, перебивание речи, DPAPI для ключей, разрешения, Esc/release-input helper и обновления/установщик. Это существующий агент, а не только чат. Реальная надёжность отдельных подсистем ограничена исходными FAIL и smoke LIMIT.

Discord в оригинале — Rich Presence, виртуальный микрофон и call-mode через звук ОС. Это не самостоятельный официальный voice-bot с подключением к каналам. Home Assistant, полноценный VRM/3D Character System и безопасная универсальная модовая платформа не обнаружены как готовые функции.

## 4. Что реально работает в форке

- Встроенная Capri — первый профиль, доступный без внешних файлов. Сохраняется существующий рендерер и его поведение.
- Каталог локальных профилей, валидация JSON/имён/renderer/личности/голоса/PNG, выбор в контекстном меню персонажа и трея. Реальный click handler пункта Luna проверен, подменю снято в PNG.
- Имя, личность, совместимые визуальные ресурсы и настройки локального голоса меняются без замены Brain. История, память, модель и провайдер сохраняются.
- Выбор восстанавливается после перезапуска; повреждённый/исчезнувший профиль даёт диагностику и fallback на Capri. Пользовательская правка личности хранится отдельно от пакета и безопасно сбрасывается.
- Проверенные сжатые PNG фиксируются в snapshot; их последующее изменение на диске не ломает ленивый рендер. Кеш имеет поколения для фоновых загрузок.
- Голосовые параметры сохраняются по id, с явным владельцем текущих настроек. Ошибки первого выбора, restart и возврата с отсутствующего персонажа закрыты регрессиями.
- Отдельные EXE/product/manifest, данные, install/uninstall/startup, locks/events, input helper, voice alias и папка клипов. Установленная Capri не заменялась; её конфигурация и история не переносились.
- Guarded по умолчанию, wake word/listen/check-ins/follow-ups/Discord presence/startup выключены в новых настройках; повреждённые permissions и crash recovery не повышают доверие.
- Upstream-установщики не используются для обновления форка. Журнал actions.log фиксирует имя инструмента и этап без аргументов/секретов; returned не означает success.
- Настоящая Gemma 4 E4B пользователя ответила через Brain из CompanionLab.exe на русском до и после смены личности. Это реальная модель, не test server.

Пример Luna использует графику Capri: отдельное оформление нового персонажа не создавалось. См. [формат профилей](docs/characters.md) и [снимок подменю](verification/ui/characters-menu.png).

Число PASS выросло не только из-за новых тестов: исходный прогон пропускал часть шагов после первого сбоя. Состав FAIL различается, поэтому совпадение числа 9 не доказывает отсутствие регрессий.

После полного прогона добавлена только дополнительная проверка настоящего клика меню/снимка подменю. Финальный EXE заново скомпилирован, профильный smoke и упаковка повторены. Повтор полного набора для этого тестового изменения не объявляется выполненным.

Независимый code review сначала заблокировал выдачу. Обнаруженные проблемы defaults, reset, mutable assets, voice ownership, permissions и проверок установщика воспроизведены и исправлены, критические сценарии закреплены тестами. Повторный независимый review после исправлений не проводился; подробности — `docs/development-evidence.md`.

Ограниченный native-shell sandbox отдельно дал 408 PASS / 27 LIMIT / 50 FAIL / 13 SKIP, включая запреты loopback/temp-файлов. Это не использовано как сопоставимый baseline; host-прогон выше выполнен через тот же Git Bash путь, что исходная Capri.

### Реальная Gemma пользователя

По ярлыку на рабочем столе найден оригинал `%LOCALAPPDATA%\Capri\Capri.exe`. В `brain/models` присутствуют E4B Q4_0 (4 590 807 392 байта) и projector (559 874 816 байт). Их SHA-256 совпали с закреплёнными в Engine.cs до и после проверки. Оригинальный EXE не запускался, файлы модели не копировались и не изменялись.

Проверка использовала отдельно скачанный официальный llama.cpp b11669 Vulkan: архив 32 182 350 байт, SHA-256 `2c07574e7bde71321cb785282b20cc821e951132149eeceeea32ddebdbf0598e`. Он проверен до исполнения. Один сервер слушал только 127.0.0.1, без инструментов управления ПК, микрофона и скриншотов. После проверки сервер завершён, VRAM вернулась к исходным 2729 MiB used / 9215 MiB free. Vision-проектор был загружен, но vision inference не тестировался.

Последний probe получил «Я Капри, и я тут, чтоб веселиться.» и «Я Луна, твой спокойный настольный компаньон.». Это проверка текстового AI и сохранения контекста, а не проверка озвучивания.

## 6. Ошибки, ограничения и риски

Полный итоговый набор остаётся красным:

1. `CheckOcr`: английская HUD-фикстура распознана с ошибками.
2. `SmokeFreeze`: Mainframe изменил minimized/normal state.
3. `SmokeGameAsks`: фраза I won't pretend приводит к лишнему `open_app:CS`.
4. `SmokeTips`: подсказка не появилась за ожидаемую задержку.
5. `SmokeFiles`: PDF continuation потерял слова пятой страницы.
6. `SmokeCallMode`: изменилось состояние окна Mainframe.
7. `SmokeTalkBrain`: timeout 180 s в socket receive/Brain.Send на локальном стенде.
8. `SmokeMinis`: не распознана фраза pull up a calculator.
9. `step 1`: проверка crash log не прошла, хотя settings recovery/сохранение ключей прошли. Assertion ожидает английский stack frame `at CapriDesktop`; локализация — вероятная причина, а не доказанное исправление.

Не все эти названия падали в baseline: часть UI-сбоев зависит от фокуса/времени, а baseline не дошёл до некоторых шагов. Они требуют отдельной стабилизации; считать их безвредными автоматически нельзя.

V1 принимает только совместимые полосы Capri с прежней геометрией. Свободные 2D layouts, VRM/3D, индивидуальные эмоции/действия и новый wake word на профиль не реализованы. Часть UI и готовых реплик сохраняет имя Capri. Облачные TTS endpoints/ключи остаются общими; per-character реализованы inherit/local/off, стили и voice-параметры.

Реальные ASR/TTS, русское произношение, облачные ключи, Discord-bot, Home Assistant и управление реальной игрой не проверялись. Общие hotkeys сохранены и могут конфликтовать с одновременно запущенной оригинальной Capri. Прикладные permission checks не являются OS sandbox и не гарантируют полное удаление секретов со скриншотов.

Пользователь остановил computer-use физическим Esc. После получения остановки работа с окнами не продолжалась; локальная Gemma проверялась headless. GUI-ветка нового launcher подготовлена, но после Esc вручную не проверялась.

## 7. Как запустить на Windows

Из корня CompanionLab для вашей установленной Gemma:

```powershell
.\ci\run-existing-gemma.ps1 -ModelDirectory "$env:LOCALAPPDATA\Capri\brain\models"
```

Скрипт использует read-only исходные веса, отдельные настройки `out/existing-gemma`, проверенный локальный runtime, один сервер и обычный EXE CompanionLab. Перед этим завершите уже работающий companion/model process сами: скрипт не останавливает чужие процессы. Для контрольной проверки без UI добавьте `-ProbeOnly`. При выходе из CompanionLab его сервер освобождается.

Для обычного запуска с самостоятельным выбором провайдера — `out/windows/CompanionLab.exe`. Сборка, UI, профили, installer и подключение собственного GitHub-fork описаны в [COMPANIONLAB.md](COMPANIONLAB.md). Сам установщик в пользовательскую систему не применялся.

## 8. Что делать следующим

Сначала стабилизировать перечисленные исходные FAIL и выполнить живые сценарии с двумя мониторами и разрешённым RU/EN ASR/TTS. Затем постепенно выделять жизненный цикл агента и формальные результаты инструментов, сохраняя текущий код. Далее — voice profiles v2, свободные 2D layouts/эмоции, 3D-адаптер, официальный Discord bot с DAVE/allowlist/приватностью, Home Assistant и игровые расширения.

Подробный [roadmap](docs/roadmap.md) содержит проверяемые границы этапов и ссылки на официальные Discord voice/self-bot требования. Всё перечисленное там является будущей работой, а не готовой интеграцией первой итерации.
